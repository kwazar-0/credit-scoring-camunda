# Персона: **ok-admin** (ADMIN)

**Пакет слотов (11):** Platform •, Release ○.  
**Назначение:** владение **организационным** и **проектным** периметром GCP, фондами политик, согласование опасных изменений; **не** ежедневный прикладной код.

**Концепция команды:** [team-11x6-organization](team-11x6-organization.md) · **EN:** [/en/team-persona-ok-admin](/en/team-persona-ok-admin)

---

## Мандат и границы

- **Владеет:** folder/project structure, квоты, org-level согласования, связка с биллингом, владелец «истины» по именованию окружений.  
- **Не владеет:** деталями RAG-промптов, схемой DMN (кроме архитектурного veto), ежедневными релизами приложения без второго лица (Release).  
- **SoD:** не должен быть **единственным** approve в `production`, если политика требует второго голоса; тогда Release — другой человек.

---

## Полный цикл разработки (SDLC) — ведущая роль по фазам

| Фаза | Действия персоны | Артефакты |
|------|------------------|-----------|
| **0–1. Инициация / дизайн** | оценка нового сервиса GCP, регион, data residency; заведение проектов dev/ref/prod | ADR, список API к включению |
| **2–3. Реализация** | ревью PR в `infra/`, `k8s/` на предмет blast radius; не блокировать мелкие фиксы без причины | approve в CODEOWNERS |
| **4–5. Тестовые среды** | контроль квот и сетевых границ ref; запрет смешения state песочницы с prod | чеклист среды |
| **6. Релизный гейт** | второй голос или владелец Environment — по матрице банка | GitHub Environment |
| **7. UAT** | обычно **не** участник (нет слота UAT/App) | — |
| **8. Операции** | эскалации по IAM, org policy; **не** замена on-call SRE для приложения | тикеты, аудит IAM |
| **9. Аудит** | подготовка **доказательств** для внешнего аудита (карта групп ↔ роли) | экспорт IAM, диаграммы |

---

## GitHub и репозиторий

- Зоны: `infra/`, корневые политики, при необходимости `SECURITY.md`.  
- Ветки: `main` / защищённые — merge только после CI и второго ревью по политике.  
- Связь: [github-codeowners-matrix](github-codeowners-matrix.md).

---

## GCP (обобщённо)

- Роли уровня **Resource Manager**, привязка групп, **не** персональные Owner на prod-проекте для всей команды.  
- Доступ к **bucket Pulumi state** — контролируемая зона; смена passphrase/backup по процедуре.

## Антипаттерны

- Выдавать себе **Owner** на prod «на время отладки».  
- Одобрять **один** крупный PR, меняющий сеть и данные, без разбиения и без Sec при чувствительных изменениях.
