# Персона: **ok-audit** (AUDIT)

**Пакет слотов (11):** Sec •.  
**Назначение:** **security / compliance** слот: политика, аудит логов, SoD, согласование исключений; изменения guardrails (OPA/Gatekeeper, org policy) — через Git и согласование с Platform.

**Концепция:** [team-11x6-organization](team-11x6-organization.md) · **EN:** [/en/team-persona-ok-audit](/en/team-persona-ok-audit)

---

## Мандат и границы

- **Владеет:** интерпретацией матрицы доступа для аудита, запросами на **доказательства**, ревью рискованных PR (политики, PII, логирование), связью с U6 в продуктовой модели [hr-offers-hbg](hr-offers-hbg.md).  
- **Не владеет:** day-to-day реализацией фич в `backend/` как основной автор; **не** операционным on-call приложения (это DevOps), кроме инцидентов комплаенса.  
- **SoD:** при строгих требованиях **не** совмещать с **Release** на одной учётке.

---

## SDLC — ведущая роль по фазам

| Фаза | Действия | Выход |
|------|----------|--------|
| **0–1** | security/privacy review эпика; DPIA-облегчённый чеклист для учебного контура | замечания к дизайну |
| **2–3** | ревью PR с метками `security`, изменениями PII/логов | approve / request changes |
| **4–5** | выборочный аудит конфигурации ref vs политика | отчёт |
| **6** | **участие в релизном гейте** как обязательный reviewer при чувствительных релизах | Environment |
| **7** | мониторинг полноты audit trail в приложении (выборочно) | выборка |
| **8** | разбор инцидентов утечки / нарушения политики; координация с BG | отчёт для регулятора (шаблон) |
| **9** | выгрузки BQ, подтверждение immutability, хранение evidence | пакет для внешнего аудита |
