# Персона: **pk-qa** (QA-TEST)

**Пакет слотов (11):** Tst-dev •, Tst-ref •.  
**Назначение:** **независимая верификация** в dev и регрессионная среда ref; **без** Pulumi и без админских ролей GCP (по умолчанию).

**Концепция:** [team-11x6-organization](team-11x6-organization.md) · **EN:** [/en/team-persona-pk-qa](/en/team-persona-pk-qa)

---

## Мандат и границы

- **Владеет:** тест-планы, автотесты в CI (триггер/ревью), качество BPMN/DMN с точки зрения покрытия сценариев, **sign-off** на ref перед передачей в релизный гейт.  
- **Не владеет:** merge в `main` без выполненных проверок; **не** изменение IaC «чтобы починить пайп».  
- **UAT/App:** у этой персоны **нет** слотов UAT/App в GCP — приёмка в prod идёт **через продукт** (другие люди бизнеса); pk-qa фокусируется на **dev/ref**.

---

## SDLC — ведущая роль по фазам

| Фаза | Действия | Выход |
|------|----------|--------|
| **1–2** | testability review дизайна (given/when/then к процессу) | комментарии к RFC |
| **3–4** | прогон CI, ручные сценарии API, worker ↔ backend, негативные PII | отчёт dev |
| **5** | **полный регресс** на ref; сравнение с эталоном; нагрузочные смоук | sign-off ref |
| **6** | **блокирующий** голос при нарушении качества — до исправления | статус в тикете релиза |
| **7** | опционально сопровождение UAT как **консультант**, не как владелец бизнес-приёмки | заметки |
| **8** | участие в разборе дефектов prod как **reproducer** | шаги воспроизведения |
| **9** | доказательства покрытия для аудита (что было протестировано) | trace к коммиту |

## GitHub

- CODEOWNERS на `bpmn/`, `dmn/`, тесты, при необходимости `.github/workflows/` (review, не секреты).

## GCP

- **View** или **read** в dev/ref по политике (логи, read-only порталы Vertex).  
- **Нет** прав на изменение prod.
