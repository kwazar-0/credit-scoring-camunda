# Персона: **sh-dev** (DEV-SH)

**Пакет слотов (11):** Dev ○, Data •, ML •.  
**Назначение:** **наклон в сторону данных и ML-инжиниринга**: ingest, качество корпуса, эмбеддинги, индекс; прикладной код там, где соприкасается с данными (`data/`, части `backend/`).

**Концепция:** [team-11x6-organization](team-11x6-organization.md) · **EN:** [/en/team-persona-sh-dev](/en/team-persona-sh-dev)

---

## Мандат и границы

- **Владеет:** `data/ingest`, выгрузки, контракты GCS-префиксов, совместно с ML — параметры индекса / eval RAG.  
- **Не владеет:** сетевой топологией VPC; **не** единоличный merge критичных infra без Platform.  
- **Dev ○:** участвует в ревью и мелких фиксах приложения, но **фокус** — Data + ML слоты.

---

## SDLC — ведущая роль по фазам

| Фаза | Действия | Выход |
|------|----------|--------|
| **1** | схема данных, SLA свежести корпуса, PII-границы | data contract |
| **2** | пайплайны ingest, job-ы BQ, скрипты в `data/` | PR |
| **3–4** | наполнение dev GCS; проверка retrieval quality | метрики eval |
| **5** | промо набора данных в ref (версионирование) | manifest версии |
| **6** | согласование «что уходит в prod-индекс» с Release/Sec | запись в change log |
| **7** | разбор инцидентов «галлюцинация / устаревший регламент» | patch данных или индекса |
| **8–9** | неизменяемость версий корпуса; след для аудита | lineage |
