# Персона: **ux-dev** (DEV-UX)

**Пакет слотов (11):** Dev •, Release •, Data ○, ML •.  
**Назначение:** **сквозной** разработчик прикладного контура: API, граф LangGraph, интеграция Vertex, участие в релизе кода; вторично — данные (согласование с Data).

**Концепция:** [team-11x6-organization](team-11x6-organization.md) · **EN:** [/en/team-persona-ux-dev](/en/team-persona-ux-dev)

---

## Мандат и границы

- **Владеет:** `backend/`, `worker/` (логика job), контракты с Zeebe, конфиг RAG в коде, тесты PyTest по своим зонам.  
- **Не владеет:** администрированием org GCP; **не** одобряет сам себя в **строгом** SoD, если он же Release — тогда нужен peer.  
- **Release •** здесь означает: ответственность за **готовность артефакта** к тегу и changelog по приложению, а не обязательно «кнопку» в Environment (она может быть у отдельного release-manager).

## SDLC — полный цикл (пример «эпик → прод»)

| Фаза | Действия | Выход |
|------|----------|--------|
| **1. Дизайн** | OpenAPI, контракт job `ai-loan-analysis`, дизайн шага графа | RFC в PR, DMN при необходимости |
| **2. Реализация** | код в `feature/*` от `develop` | PR, юнит-тесты |
| **3. Интеграция dev** | локально compose или dev-кластер; проверка с mock/real vector по [ml-data-rag](ml-data-rag.md) | CI green |
| **4. Верификация dev** | совместно с **pk-qa**: сценарии API и worker | чеклист |
| **5. ref** | merge в `release/*` по [git-workflow](git-workflow.md); регресс | стабильный ref |
| **6. prod** | после approve Environment — только образ/манифест из CI | тег `v*` |
| **7. UAT** | поддержка дефектов «как в приложении» | фиксы в патч-ветке |
| **8–9** | участие в postmortem как автор изменений; **не** правка аудит-логов | RCA |
